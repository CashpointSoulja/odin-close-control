# Close Control threat model

I designed this public concept for anonymous visitors working only with synthetic records. The assets worth protecting are session isolation, correct cash arithmetic, accurate exception visibility, revision integrity, review freshness and bounded storage usage. The application has no payment authority, banking connection, real identity evidence or confidential document store.

The browser is untrusted. It may send fabricated revisions, unknown identifiers, oversized bodies or concurrent operations. The Worker owns validation and state changes. D1 is the storage trust boundary. The session cookie is a bearer secret: possession permits access to that synthetic session.

| Threat | Control in this concept | Remaining boundary |
| --- | --- | --- |
| One visitor reads or changes another visitor's state | Random 256-bit session secret; only its digest stored; every read and update scoped to that digest; HttpOnly, Strict SameSite and Secure cookies outside localhost | Cookie theft can still expose its synthetic session. This is not account authentication. |
| A stale tab overwrites newer work | Required expected revision, server recalculation, bound SQL update constrained by old revision and expiry; conflict returns 409 | A client must reload and repeat its decision after a conflict. |
| Cross-site mutation | Same-origin Origin/Fetch-Site checks, JSON-only writes, Strict SameSite cookie, no permissive CORS headers | Non-browser clients may omit Origin; the API remains anonymous and accepts only synthetic schema. |
| Script or markup injection | External scripts/styles restricted to self by CSP; no inline-script allowance; no-sniff, frame restriction, fixed fixture labels and strict input schema | The frontend must continue rendering imported values as text and keep dependencies reviewed. |
| SQL injection or sensitive error leakage | All SQL values bound; unknown request fields rejected; unexpected failures return a generic message without SQL, stack, cookies or submitted content | Infrastructure logs and access policies still need deliberate production configuration. |
| Resource exhaustion | Actual request bytes capped at 70 KiB, each CSV at 32 KiB/100 rows; event/commitment/audit bounds; D1 session and creation counters; 24-hour session expiry | Creation limiting trusts `CF-Connecting-IP` only at Cloudflare ingress; a different proxy requires a trusted replacement. Fixed windows are not a full bot defence. A production service needs quotas and alerts. |
| Floating point loss, overflow or hidden cash mismatch | String minor units, bounded BigInt arithmetic, currency-specific parsing, explicit fee rounding and per-account balances | Illustrative fee assumptions require internal validation before operational use. |
| Duplicate, wrong-currency or guessed receipts manufacture readiness | Canonical event idempotence; conflicting reuse rejected; shared settlement references quarantined; explicit matching/exclusion; wrong currency blocked | A human exclusion is an attestation, not independent bank evidence. |
| Refunds or reversals reduce the wrong balance | Original-settlement parent required in the same deal/currency; positive adjustment amounts; aggregate bounded by parent; no adjustment chaining | There is no live settlement feed or external transaction verification. |
| Approval reused after changed records | Review request and approval bind current revision and hash, including raw records and derived reconciliation; all changing operations invalidate review; export rechecks readiness and approved hash | A hash checks snapshot integrity. It does not verify signer identity or provide a reviewer signature. Known operator/reviewer labels do not enforce real roles or separation of duties. |
| Legal/KYC evidence overstates certainty | Only fixed synthetic legal metadata and known demo actors accepted; review and export carry synthetic notices | A recorded digest does not verify a document; a boolean does not complete a regulatory check. |
| CSV spreadsheet formula execution | Quoted CSV output, escaped quotes and apostrophe prefix for formula-leading cells | Downstream spreadsheet handling is outside this application. |

I verify the state boundary with Worker/D1 integration tests for independent visitors, stale concurrent writes, expiry, preview binding, atomic invalid imports, duplicate-import idempotence, request guards, reviewed export freshness and rate caps. Domain tests cover financial and workflow invariants separately. These tests establish the prototype's implemented behaviour; they are not a certification or evidence of Odin's internal controls.

Before admitting real data, I would replace anonymous access with authenticated users and server-enforced roles, separate immutable financial records from session state, define approval authority and retention with the operations team, verify source documents and settlement evidence, add monitoring and backups, and validate the entire closing workflow with internal owners. A real deployment would also need provider credentials, a real D1 identifier and deployment-specific controls. The current default remains a synthetic demonstration.
